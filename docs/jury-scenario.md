# Сценарий для жюри

## Автономная проверка

1. Зафиксировать проверяемый commit: `git rev-parse HEAD`.
2. Выполнить `docker compose up --build --wait`.
3. Открыть http://localhost:8501, нажать «Открыть бизнес-аналитику».
4. Оставить демонстрационные события, перевозчика и казначея.
   Ожидание: есть события ставки/валюты, вывод по профилю, датированные материалы банка и журнал.
5. Открыть журнал. Убедиться, что он содержит план, профиль, платежи, ранжирование,
   выбор карточек банка и результат проверки. Нет ключа — честно указан режим правил.
6. Выбрать общепит, казначея. Новость только о ставке, значимая перевозчику с лизингом,
   не должна появиться в его ленте. Затем выбрать собственника: приоритет получает спрос.
7. Добавить новую новость: заголовок «Спрос в ресторанах меняется», текст
   «Вымышленный опрос показывает рост потребления и спроса в общепите», дата 21.10.2026.
   Ожидание: новая карточка проходит обработку и появляется в ленте.
8. Ввести вопрос «Что означает изменение спроса?», нажать «Подготовить анализ».
   Ожидание: в журнале `focused_search`, компания/роль остаются прежними.
9. Скачать JSON: версия схемы, контекст, источники, выводы, шаги, пробелы данных.
10. Прогнать тесты командой из README, остановить Compose.

## Проверка LLM с ключом организаторов

1. Заполнить `.env` по README и пересоздать контейнер.
2. Проверить, что интерфейс показывает разрешённое имя модели.
3. Задать вопрос о финансировании перевозчика и нажать «Подготовить анализ».
4. В успешном ответе — четыре блока, источники у каждого, отдельная позиция банка.
5. Журнал содержит `interpret` и `validate`; при ошибке ответа — `repair` и вторую проверку.
6. Если шлюз/ответ недоступен, интерфейс сохраняет ленту и явно показывает режим правил.

Детерминированные тесты `tests/test_agent.py` воспроизводят неверное число, неизвестную ссылку,
успешное исправление, исчерпание двух попыток и отказ шлюза без расходования токенов.
Реальную модель следует проверить с разрешённым ключом перед демонстрацией.

## Нештатные данные

- Будущая публикация: скрыта, дата не меняется автоматически.
- RSS без даты или корректной ссылки: запись пропускается.
- Новость без совпадающих факторов: не попадает в ленту.
- Недоступные RSS: прежняя живая лента сохраняется; синтетика не подменяет её молча.
- Неизвестный клиент: агент сообщает, что нужен профиль; реальная организация не угадывается.
- Пустой/нечитаемый CSV: понятное сообщение вместо падения UI.
- Нет платежей: анализ продолжает работу с явным пробелом в данных.
