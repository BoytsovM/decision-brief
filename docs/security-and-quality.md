# Безопасность, качество и развитие

## Реализовано в прототипе

- Собственный планировщик выбирает инструменты по доступным данным и теме вопроса.
  Его права ограничены чтением; LLM не исполняет Python, shell, SQL и сетевые инструменты.
- Новости и вопрос передаются как данные в JSON. Системная инструкция запрещает выполнять
  встроенные в них команды. Это снижение риска prompt injection, не доказанная полная защита.
- Перед моделью выполняются классификация и отбор. В запросе максимум три новости,
  каждый текст ограничен; физлица и полный клиентский CSV не отправляются.
  Выбранный профиль, агрегированные связи и ID контрагентов при подключённом шлюзе отправляются:
  оператор должен использовать разрешённую среду кейса и синтетические данные для публичного демо.
- Секрет задаётся окружением, не попадает в журнал, экспорт или repr клиента.
- HTTPS с проверкой сертификата; небезопасный повтор с отключённым TLS удалён.
  Модельный клиент не следует перенаправлениям с секретом.
- RSS-адреса фиксированы. Пользователь может загрузить файл/текст; произвольные введённые URL
  не скачиваются. Размер RSS ограничен 2 МБ; новостей из загрузки до 100.
- Allowlist моделей соответствует приложению 3 задания. До двух вызовов на анализ,
  таймаут 30 секунд, до 1200 токенов ответа. Денежный лимит обеспечивает шлюз организаторов.
- JSON ответа проверяется по обязательным полям, источникам и числам внутри указанных источников.
  Числа из вопроса не считаются подтверждёнными. Повторная неудача возвращает режим правил.
- Позиция банка формируется из датированных карточек, отдельно от ответа модели.
  Прогнозы не называются фактами. Будущие, устаревшие и тематически неподходящие материалы
  исключаются агентом; обзор золота не используется для вывода о стали.
- Контейнер работает без root, с read-only файловой системой, tmpfs, без capabilities.
  По умолчанию порт опубликован только на 127.0.0.1.
- Журнал и обратная связь находятся в сессии браузера; постоянного серверного хранилища нет.

## Для интеграции в банк

1. OIDC/SSO перед UI и серверная проверка привязки пользователя к компании при каждом запросе.
   Выбор роли в демонстрации не является механизмом авторизации.
2. Изолированные tenant-контексты, минимизация/псевдонимизация признаков, защищённый секретный storage.
3. Сервис чтения источников с egress allowlist, расписанием, кешем и защитой от SSRF на redirect.
4. Версионируемое хранилище документов с source ID, датой, страницей, checksum и ручным подтверждением
   OCR; старые версии и конфликтующие прогнозы доступны для аудита.
5. Очередь задач, отдельные воркеры чтения и интерпретации, индекс по факторам/отраслям,
   ключ кеша `(tenant, profile_version, role, news_version, model_version)`.
6. Централизованный журнал без секретов и полных платёжных данных, квоты на пользователя,
   учёт токенов/денег, срок хранения, ручная эскалация спорных материалов.

## Метрики и процедура

Значения ниже — предлагаемые критерии, а не измеренные результаты модели.

| Что измерять | Метод |
| --- | --- |
| Precision@5 и nDCG@5 персонализации | Независимая разметка новости для профиля и роли, отдельный от разработки набор |
| Полнота/точность цитирования | Доля ключевых утверждений с действительно подтверждающим источником и страницей |
| Неподтверждённые числа | Доля принятых числовых утверждений без опоры в процитированном материале |
| Факт / прогноз / вывод модели | Экспертная проверка смешения категорий и несовместимых дат |
| Исправления и отказы | Доли repair, model_rejected, model_failed и причин отсутствия источников |
| Работа на новых событиях | Набор ранее не использованных новостей из разных отраслей, включая нерелевантные |
| Польза и ясность | Оценки пользователей плюс разбор ошибочных ответов экспертами банка |
| Производительность | p50/p95 задержки, размер запроса, число вызовов и стоимость на завершённый анализ |

На каждом изменении: unit/UI-регрессия и независимый holdout-набор; еженедельно — выборочный
экспертный аудит и проверка свежести карточек. Изменения весов/порогов/модели версионируются.
Сейчас качественная проверка LLM не проведена: ключ не предоставлен. Один тест внешнего XLSX
пропущен из-за отсутствия исходного файла. Не следует выдавать число пройденных тестов
за точность персонализации или достоверность генерации.
