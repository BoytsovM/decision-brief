# decision-brief

Персональная сводка внешней новости для конкретной компании. Хакатон «Альфа Будущее».

Позиция Альфа-Банка и вывод модели — разные блоки. Вывод ссылается на источник новости. Число в выводе модели остаётся только если оно уже было во входных полях.

## Назначение

Экран показывает ленту для одной компании и одной роли. У карточки шесть блоков: что произошло, почему этой компании, последствия, как оценивает банк, вывод модели, источник.

Позиция банка берётся из карточек K1–K9 в `src/decision_brief/bank_cards.py`. PDF банка в рантайме не читаются: это сканы без текстового слоя. Сталь 2021 (карточка K6, `ALFA_Russian_Steels_1K21.pdf`) скрыта: у неё `fresh=False`, в ленту и в блок банка она не попадает. Модель заполняет только блок «Вывод модели» и не переписывает блок «Как оценивает банк». Полный CSV в git не входит: каталог `data/raw/` указан в `.gitignore`.

Без полного файла экран читает синтетический `data/sample/companies.csv`. В демо-наборе три компании с выручкой от 15 млрд руб. Строка `U_428697` и компания с выручкой 1 млрд руб. в список не попадают.

## Архитектура

Отдельного фронтенда нет. Экран — Streamlit.

1. `feeds.py` читает шесть публичных RSS и разбирает их через `parse_rss`. Силу фактора внутри `parse_rss` по-прежнему ставит `factors_in_text`.
2. `companies.py` читает CSV через `load_companies` и оставляет демо-набор: собственная выручка компании от 15 млрд руб.
3. `scoring.py` считает, насколько новость бьёт по компании. Материал старше года получает 0. Этот расчёт не менялся.
4. `roles.py` умножает уже посчитанный скор на вес роли. Роли: казначей, главбух, собственник. Пороги прежние: от 0,6 «важно», от 0,3 «к сведению», ниже скрыто.
5. `bank_cards.py` подставляет самую свежую карточку по главному фактору. K6 в этот выбор не входит.
6. `conclusion.py` заполняет только блок «Вывод модели», и только если заданы три переменные окружения. Имя с `Qwen3-VL` или фрагментом `-vl` клиента не создаёт. Адрес шлюза в код не записан.
7. `app.py` рисует ленту. Смена компании или роли меняет состав и порядок. Ошибка загрузки RSS не стирает уже посчитанную ленту.

Своя модель не обучается. Qwen3-VL в ответ пользователю не вызывается. Готовый мультиагентный фреймворк ядром не используется.

Сигнатуры `score_item`, `rank_for_company`, `explain`, `parse_rss`, `factors_in_text` и `load_companies` не менялись.

## Окружение

- Python 3.12 в образе `python:3.12-slim-bookworm`. Локальный интерпретатор подойдёт, если он не старше 3.12.
- Docker с поддержкой `docker compose`.
- Сеть на время показа ленты: экран ходит в шесть RSS. Тесты сеть не открывают.
- Ключ шлюза не нужен, чтобы поднять экран. Без него блок «Вывод модели» пустой.

Зависимости зафиксированы в `requirements.txt`. Прямая зависимость — `streamlit==1.66.0`, остальное дерево тоже закреплено версиями. Ставить пакеты для проверки нужно из этого файла, а не заново разрешать `streamlit>=…`.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `DECISION_BRIEF_MODEL` | Имя текстовой модели из списка кейса. Пустое значение клиента не создаёт. |
| `DECISION_BRIEF_BASE_URL` | Базовый URL шлюза chat completions. Пустой адрес публичным API не заменяется. Если путь уже кончается на `/chat/completions`, он используется как есть. |
| `DECISION_BRIEF_API_KEY` | Ключ шлюза. В репозитории ключа нет. |
| `DECISION_BRIEF_COMPANIES` | Необязательный путь к CSV компаний с разделителем `;`. Если переменная не задана, берётся `data/raw/df_Uid_data_hack.csv`, когда файл лежит на диске, иначе `data/sample/companies.csv`. |
| `PYTHONPATH` | Для локального запуска без установки пакета: `src`. В образе уже равен `/app/src`. |

Разрешённые кейсом модели и отказ для Qwen3-VL перечислены в `THIRD_PARTY_NOTICES`.

Пример вызова модели, когда известны шлюз, имя и ключ:

```powershell
$env:DECISION_BRIEF_MODEL = "Qwen3.6 35B A3B"
$env:DECISION_BRIEF_BASE_URL = "<базовый URL шлюза>"
$env:DECISION_BRIEF_API_KEY = "<ключ>"
```

Имя `Qwen3-VL-30B-A3B-Instruct` клиент не создаёт.

## Одна команда запуска экрана

Из корня репозитория:

```text
docker compose up --build
```

Образ собирается из `Dockerfile`, полный CSV в него не копируется. Экран слушает `http://localhost:8501` и читает синтетический CSV. Для этой команды `DECISION_BRIEF_COMPANIES` лучше не задавать: иначе в контейнер попадёт путь с хоста. Остановка: Ctrl+C, затем `docker compose down`.

Три переменные модели, если они уже есть в окружении shell, попадают в контейнер. Пустые значения блок модели не заполняют.

## Пошаговый сценарий проверки

Чистая копия репозитория, без `data/raw/` и без заранее созданного `.venv`.

1. Запустить экран:

```text
docker compose up --build
```

2. Открыть `http://localhost:8501`. В подписи указан синтетический файл. В списке «Компания» три строки: `U_sample_transport`, `U_sample_horeca`, `U_sample_housing`. Рядом роль: казначей, главбух или собственник.
3. Дождаться ленты. У карточки шесть блоков. «Как оценивает банк» цитирует свежую карточку K1–K9, не текст модели. K6 (сталь 2021) в этом блоке не появляется. «Вывод модели» без трёх переменных показывает «Пусто: нет ключа модели.» У источника ссылка, если адрес начинается с `http://` или `https://`.
4. Сменить компанию с перевозчика на общепит и роль. Состав и порядок ленты меняются. Новость, которая видна перевозчику, может быть скрыта у общепита: порог скоринга тот же.
5. Нажать «Обновить ленту». Если все адреса RSS недоступны, уже показанная лента остаётся, на экране написано, что показана уже посчитанная лента.
6. Остановить контейнер: Ctrl+C, затем `docker compose down`.
7. Прогнать тесты в том же образе, без полного CSV и без сети:

```text
docker compose run --rm --build --entrypoint python screen -m unittest discover -s tests
```

Ожидание: ошибки нет. Один тест пропускается, если в репозитории нет xlsx с восемью эталонами. Это известный пропуск, не падение.

Локально, если Docker не используется, из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m unittest discover -s tests
$env:DECISION_BRIEF_COMPANIES = "data/sample/companies.csv"
.\.venv\Scripts\python.exe -m streamlit run src/decision_brief/app.py
```

`DECISION_BRIEF_COMPANIES` нужен локально только когда в `data/raw/` уже лежит полный файл: без переменной экран откроет его. В контейнере полного файла нет, переменная не нужна.

## Как сменить клиента

Клиент — компания в списке «Компания». Роль меняется в соседнем списке.

Синтетический набор:

| Идентификатор | Кто это | Зачем в наборе |
| --- | --- | --- |
| `U_sample_transport` | Грузоперевозки, ОКВЭД 49.41, 32,3 млрд руб., лизинг, штат больше 100, ВЭД | Новость о ставке у казначея остаётся в ленте |
| `U_sample_horeca` | Общепит, ОКВЭД 56.10, 20 млрд руб. | Та же новость о ставке у казначея скрыта |
| `U_sample_housing` | Жилищное строительство, ОКВЭД 41.20, 18 млрд руб., кредит | Новость о ставке остаётся, поля CSV другие |

`U_428697` и `U_sample_small` в файле есть и в список не выводятся.

Полный демо-набор из 115 компаний: положить `df_Uid_data_hack.csv` в `data/raw/` и перезапустить экран. Файл в git не коммитить. В Docker тот же файл подключается томом и в образ не копируется. Этот запуск вместо `docker compose up`:

```text
docker compose run --rm --service-ports -v ./data/raw:/app/data/raw:ro screen
```

Обычный `docker compose up` том не монтирует, поэтому экран остаётся на синтетике. Другой CSV с теми же колонками и разделителем `;`:

```powershell
$env:DECISION_BRIEF_COMPANIES = "data/sample/companies.csv"
```

В контейнере путь считается от `/app`.

## Что сознательно не входит в запуск

Полные `df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv` и `df_Fid_Uid_link_hack.csv` остаются только в `data/raw/` на машине, где их положили вручную. Экран платежи и связку физлиц не открывает. PDF банка не парсятся. Своя модель не обучается.
