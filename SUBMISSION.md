# Комплект для сдачи

Репозиторий: https://github.com/BoytsovM/decision-brief

Подготовленная версия находится в ветке **`submission/jury-ready`**.
Для сдачи укажите полный commit hash проверенной версии. После скачивания ветки:

```bash
git rev-parse HEAD
```

Ветка может обновляться, поэтому ссылка на неё не заменяет commit hash при сдаче.
Git bundle сам по себе не обновляет GitHub. До отправки убедитесь, что указанный commit
доступен в репозитории и проверки GitHub Actions завершились успешно. Если дополнительно
создаёте тег, не перемещайте его после подачи решения.
PDF не содержит календарной даты дедлайна; сроки нужно сверить с регламентом организаторов.

## Проверено при подготовке

- Чистое виртуальное окружение Python 3.12.14 и установка всего requirements.txt.
- `pip check`: конфликтов зависимостей нет.
- 100 тестов: 99 пройдены, один старый тест XLSX пропущен, потому что файл эталонов отсутствует.
- Настоящий сценарий Streamlit AppTest: главная → аналитика → компания/роль → новая новость → вопрос.
- Локальный сервер Streamlit: HTTP `/_stcore/health` возвращает `200 ok`.
- Существование указанного Docker image tag и digest проверено в реестре.
- Используемые банковские тезисы сверены с исходными страницами PDF.

**Не выдаётся за проверенное:** реальный LLM-вызов (нет настроек шлюза команды),
локальная Docker-сборка (в среде подготовки нет Docker Engine), независимая оценка качества
на XLSX-эталонах, внешнее размещение. CI описывает сборку и контейнерный smoke test,
но его результат нужно проверить после публикации на GitHub.

## Публикация подготовленной версии

Если получен архив: распакуйте его. В `source/` можно сразу запускать Docker.
Для восстановления полной истории:

```bash
git clone -b submission/jury-ready decision-brief.bundle decision-brief
cd decision-brief
git remote set-url origin https://github.com/BoytsovM/decision-brief.git
git push origin submission/jury-ready
```

Либо импортируйте ветку в существующий clone:

```bash
git fetch /absolute/path/decision-brief.bundle submission/jury-ready:submission/jury-ready
git switch submission/jury-ready
git push origin submission/jury-ready
```

Основную ветку и существующие коммиты не требуется переписывать. При желании влейте ветку
обычным pull request и зафиксируйте тот hash, который действительно отправляете жюри.

Если репозиторий приватный, владелец должен предоставить доступ аккаунту **alfa-hack-2026**.
У этой подготовки нет сведений о статусе такого доступа. Публичный внешний сервер в задании
рекомендован, но не обязателен. Для полного AI-показа подключите ключ разрешённого шлюза
через `.env` и выполните второй раздел сценария проверки.

## Создание архива повторно

После коммита всех изменений:

```bash
python scripts/package_submission.py --output ../decision-brief-submission.zip
```

Скрипт включает только отслеживаемые файлы текущего коммита, Git bundle с историей,
VERSION.json и SHA-256 для файлов. `.env`, `.venv` и `data/raw` в пакет не попадут.
Незакоммиченные изменения приводят к отказу, а не к незаметно неполной сдаче.
